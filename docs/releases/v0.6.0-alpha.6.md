# v0.6.0-alpha.6 — Nextcloud application-aware local recovery candidate

Sixth bounded Phase 5 prerelease. **Phase 5 is not complete and production Nextcloud is not adopted.**

## Included

- Exact digest pins for Nextcloud 34.0.5 Apache, PostgreSQL 18 and Redis 8.2 Alpine.
- Loopback-only app access, internal dependency networking, file-based generated secrets, separate cron and explicit resource/log limits.
- Exact WebDAV upload/download evidence and contention-safe execution of one real cron cycle.
- Maintenance-mode, application-quiesced PostgreSQL/config/data/custom-apps/themes backup with the private application database role, sanitized metadata and complete checksums.
- Fresh-project restore with derived-core initialization, preserved database ownership, exact content comparison and recovered stop/start persistence.
- Focused tests, Windows batch ACL verification, module/operator documentation and an expanded Phase 5 release validator.

## Release decision

Go for `0.6.0-alpha.6` only after repository, Phase 4/5, publication, whitespace and complete cross-platform unit-test gates pass on the exact commit. No-go for stable `0.6.0`, production migration or replacement of the owner's backup process.

## Boundaries

The backup remains plaintext-sensitive and local. External storage, the existing custom SMB image, native clients, public access, mail/SSO, encryption-app keys, upgrades, representative scale, scheduling, 7/4/3 retention, durable off-host storage and real offline-key custody are not certified. Linux/macOS/ARM64 live runtime evidence is absent.

The existing personal Nextcloud deployment remained outside this adapter. No personal users, files, credentials, external drives or database rows were copied or changed.

## Next gate

Add separately keyed encryption and path-independent off-host recovery on an unrelated clean runner, then decide whether production adoption can be planned. Phase 5 does not advance to Firefly III until an explicit separate command.
