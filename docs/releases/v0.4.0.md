# v0.4.0 — Storage, secrets and safe execution

Synthetic-only prerelease. No production application installer or disaster-recovery certification.

## Delivered

- Separate `sandbox plan`, `apply`, `status` and `retire` commands, requiring reviewed-plan confirmation for mutations.
- Configurable, dedicated installation/data/backup-staging roots; refusal of existing unowned paths, Git paths, symlinks/junctions and hard-linked private files.
- Windows owner/DACL and POSIX owner/mode enforcement on private state; no global elevation or permission changes to existing folders.
- Generated 256-bit synthetic credential with reference-only reports, reuse across retries and fingerprint drift detection.
- Kernel operation locks, atomic state snapshots, ownership markers, ordered journal transitions and actual-content verification.
- Data-preserving retirement of the exact synthetic activation receipt only.
- [Usage, recovery boundaries and security limitations](../safe-execution.md).

## Validation scope

The cross-platform suite contains 126 tests, including real filesystem and process-lock tests. Platform-specific tests skip where inapplicable; local Windows symlink creation may be unavailable. Windows tests exercise actual DACL creation and rejection of an added public reader. POSIX tests check owner-only modes and refusal of permission drift.

Interruption evidence includes completed-operation boundaries, forced process exit after credential creation, kernel-lock release on process death and interrupted retirement. Failed atomic replacement preserves prior state and pending evidence. Ambiguous initialization or atomic-publication residue deliberately requires manual review; arbitrary power-loss recovery is not certified.

CI covers Windows/Linux/macOS with Python 3.12 and 3.14, existing planner/collector regressions and platform launchers. This is **not** Docker/application deployment evidence. Publication review excludes all private runtime state and generated tokens.

## Not included

Docker execution or real service adapters, automatic adoption, encrypted recovery bundles, backup/restore, upgrades, data deletion, network/public access, GPU support and production resource tuning. The synthetic backup root is reserved only; no backup is created.

Phase 4 begins only after explicit authorization and introduces independently tested application modules. Existing homelab services remain outside this executor's ownership.
