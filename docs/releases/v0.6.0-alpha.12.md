# v0.6.0-alpha.12 — Karakeep application-aware recovery candidate

Twelfth bounded Phase 5 prerelease. **Phase 5 is not complete and production Karakeep is not adopted.**

## Included

- Digest-pinned Karakeep 0.34.1, Karakeep Chrome, Meilisearch 1.41.0 and Playwright/Chromium 1.64.0.
- Loopback-only app access, an internal bridge, generated secrets, explicit users, read-only roots, dropped capabilities and bounded resources.
- Rendered first-user/API-key workflow plus exact text bookmark, full-text search and PNG asset upload/download validation.
- Built-in logical export verification for the text bookmark as supplementary evidence, with binary asset recovery kept in the authoritative asset tree.
- Quiesced SQLite and asset-tree backup with `PRAGMA quick_check`, sanitized metadata and complete checksums; queue, WAL/SHM and Meilisearch state are excluded.
- Fresh-project recovery that rebuilds the search index from the restored database, verifies exact rendered/search/asset semantics and repeats them after restart.
- Focused contract/tamper tests and expanded Phase 5 validation.

## Release decision

The isolated Windows Docker Desktop source/backup/fresh-restore rehearsal passed. Go for `0.6.0-alpha.12` only after the standard cross-platform CI also passes on the exact commit. No-go for stable `0.6.0`, production migration or replacement of the owner's backup process.

## Boundaries

The staging backup contains generated credentials and is not encrypted. Registration is enabled only for the disposable fixture; AI, embeddings, LLM OCR, mail, public access, Docker control and devices are disabled. The existing personal Karakeep deployment remains outside this adapter.

This candidate does not validate personal data, multi-user use, link crawling, archived pages, PDFs/OCR, large assets, external AI, native clients, SMTP, public access, load, upgrades, rollback, encrypted off-host storage, scheduling, retention or non-Windows runtime behavior.

## Next gate

Encrypted off-host Karakeep recovery is a separate milestone requiring a reviewed backup tool, independent recovery-key custody, encrypted-only transfer and fresh-runner browser/search/asset recovery.
