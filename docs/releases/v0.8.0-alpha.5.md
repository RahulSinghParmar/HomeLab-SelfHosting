# 0.8.0-alpha.5 — Matrix, Element and optional TURN integration

This prerelease adds a strict integration plan/evidence contract and records the live Matrix/Element and TURN preflight on the reference Windows host.

## Delivered

- Matrix/Element identity, endpoint, loopback and restart-persistence gates.
- Optional TURN semantics that cannot pass without direct DNS, external UDP/TCP STUN, authenticated relay and real audio/video call evidence.
- A secret-free Python STUN probe for Windows, Linux and macOS.
- A manual least-privilege GitHub workflow for independent internet probing and optional temporary relay credentials.
- Read-only reference-host validation of Synapse, Element, `.well-known`, native Cloudflare Tunnel, coturn configuration and shared-secret parity.
- Production Synapse and Element direct ports restricted to loopback with an exact Compose rollback copy, no image pull, controlled restart, unchanged signing-key hash and successful local/public health.
- Explicit diagnosis of the stale TURN record: the dedicated DDNS token's client-IP filter rejects the host after its public address changed.
- Focused regression tests, Phase 7 release guards and operator documentation.

## Not claimed

- Working public TURN relay or successful cross-network Element calls.
- Production migration away from floating image tags.
- Production-consistent encrypted Matrix recovery or client E2EE-key recovery.
- Federation, bridge recovery or automatic firewall/router configuration.
- arm64 runtime execution.

Matrix messaging and Element public access remained healthy. TURN stays optional and uncertified until the owner repairs the dedicated DDNS token and the independent relay/call gates pass.
