# v0.6.0-alpha.13 — Karakeep encrypted off-host recovery candidate

Thirteenth bounded Phase 5 prerelease. **Phase 5 is not complete and production Karakeep is not adopted.**

## Included

- Reviewed Restic 0.19.1 Windows/Linux amd64 tool identities with exact archive and executable checksums.
- Separate operational and recovery-key files, private plan/state roots, hidden Restic error output and non-overlapping plaintext, encrypted and key locations.
- Confirmation-gated encrypted store, full repository data read, exact snapshot restore, portable recovery manifest and restore-gated 7-daily/4-weekly/3-monthly retention.
- A manual two-runner workflow that transports only the encrypted repository and nonsecret manifest while injecting the recovery secret independently.
- Clean-runner reconstruction of a fresh Karakeep instance with rendered bookmark verification, rebuilt full-text search, exact binary-asset download and restart persistence.
- Linux containers run as the numeric owner of their private bind directory, retaining `0700/0600` host permissions, `cap_drop: ALL` and a private owner-matched `/tmp` instead of broadening filesystem access.
- Eighteen focused encrypted-vault tests plus the eleven existing application-recovery tests and expanded offline Phase 5 validation.

## Release decision

Go for `0.6.0-alpha.13` only after the standard cross-platform matrix and both jobs of the manual off-host recovery rehearsal pass on the exact commit. No-go for stable `0.6.0`, production migration or replacement of the owner's backup process.

## Boundaries

The local staging backup remains plaintext-sensitive until encrypted. Same-host repository and key copies are test evidence, not disaster recovery. The production vault is not read, exported, modified, stopped or restarted.

This candidate does not provide durable owner-operated off-host storage, real offline-key custody, scheduling, key rotation, large-archive evidence, link-rot handling, tags/lists, browser-extension behavior, public access, multi-user/load behavior, upgrade rollback, ARM64 or macOS runtime evidence.

## Next gate

All selected Phase 5 applications now have bounded recovery modules; integrated disaster-recovery review and production adoption remain separate owner-approved gates.
