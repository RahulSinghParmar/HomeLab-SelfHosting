# v0.3.0 — Doctor, wizard and deployment planning

Planning prerelease. No application installer or production-readiness claim.

## Delivered

- Python 3.12+ `catalog`, `configure`, `validate`, `doctor` and `plan` commands; PowerShell and POSIX launchers without implicit installs/elevation.
- Strict settings schema, interactive/file-based configuration, three platform examples and 21-module planning metadata.
- Deterministic dependency ordering, redacted/hash-bound review plans, configurable TCP/UDP ranges, storage proposals and provisional resource budgets.
- Read-only host checks with remote-context refusal, existing-project/port checks, missing/occupied storage detection and explicit unknown results.
- Exclusive private JSON output outside Git, with no overwrite and no runtime storage creation.
- [Usage and limitations](../planning.md), updated architecture/support guidance and failure-case tests.

## Verification

- 98 Python regression tests; the local restricted Windows run skips one real symlink fixture because link creation is unavailable. A mocked link guard is still tested; CI exercises native link behavior where permitted. Launcher tests check actual JSON output and failure exit codes, not just a successful process exit.
- Repository validation covers 21 modules, all discovery runbooks, three historical design fixtures and three runnable settings examples.
- CI matrix: Windows, Linux and macOS with Python 3.12/3.14; offline plan and native launcher smoke checks. Live Linux/macOS Docker behavior is not established by these tests.
- Windows reference doctor exercised the actual local Linux-container Docker engine and correctly found occupied example ports and missing example drives. No lifecycle or production configuration operations are implemented or performed.
- Publication guard and manual diff review are required before publishing the tag; local reports remain outside Git.

## Not included

Application templates or deployment, ownership/adoption, secret generation, backup/restore, image/GPU validation, registry pulls, public DNS/tunnel setup, production resource tuning or automatic conflict repair. All modules remain planned. Estimates are not enforced limits or measured capacity.

Next authorized milestone: Phase 3 safe primitives and synthetic execution tests, not bulk deployment of the existing homelab.
