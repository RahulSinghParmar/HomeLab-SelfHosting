# v0.5.0-alpha.1 — Isolated Glance starter

First bounded Phase 4 prerelease. **Phase 4 is not complete.** This is not production certification or a clone of the existing private dashboard.

## Delivered

- Separate `glance plan/up/status/stop/remove/export` interface and integrity-checked starter recovery into a fresh installation.
- Original two-page starter with synthetic success/failure checks; no private accounts, statistics, feeds or API keys.
- Digest-pinned Glance v0.8.6, cached-image-only execution and exact local engine binding.
- Loopback-only published port, dedicated bridge (outbound allowed), read-only root/configuration, no Docker socket, bounded CPU/RAM/processes/logging.
- Private state, process locks, ownership/drift checks, confirmation gates, idempotent retry and data-preserving cleanup.
- [Usage and explicit limitations](../glance-module.md).

## Validation evidence

Live Windows Docker Desktop with Linux amd64 Engine 29.8.1, local private filesystem and synthetic data only:

- Fresh startup and actual browser rendering of Home and Operations.
- Self-check rendered OK; deliberately unavailable fixture rendered ERROR. This is not yet a Kuma alert-transition test.
- Retry preserved container identity and startup timestamp; stop/start preserved configuration and page content.
- Configuration exported and verified, then recovered into a different root/project/loopback port; SHA-256 matched and rendered content was checked.
- Trials are stopped and their exact owned containers/networks removed after verification; private configuration, state and export are retained. No production cleanup commands are used.
- An internal-only bridge accepted a port request but left no effective published port. Changed the trial to a dedicated bridge with loopback binding and added a regression guard for requested-but-unpublished ports.
- Initial idle sample: 8.375 MiB RAM / 128 MiB ceiling, 0.00% CPU, four processes. This is a point-in-time lightweight starter measurement, not a long-duration/load benchmark or sizing recommendation for a populated dashboard.
- Post-restart/recovery samples: original 6.215 MiB and fresh recovery 5.633 MiB, each at 0.00% CPU. No heavy load benchmark was performed.

The suite adds 26 Glance regressions to the previous 126 tests. It uses synthetic Docker responses plus real private filesystem/lock checks; CI on Windows/Linux/macOS does not deploy application containers. Review the release commit's six-job CI result before use. All private plans, engine identifiers, paths and exported configuration stay outside Git.
