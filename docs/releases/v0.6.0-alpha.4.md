# v0.6.0-alpha.4 — AFFiNE application-aware recovery candidate

Fourth bounded Phase 5 prerelease. **Phase 5 is not complete and production AFFiNE is not adopted.**

## Included

- Digest-pinned AFFiNE 0.27.4, PostgreSQL pgvector pg16 and Redis 8 Alpine in a fresh loopback-only project.
- Expected one-shot migration lifecycle, private generated credentials, internal dependency networking, explicit security controls and bounded resources.
- A nonempty AFFiNE workspace/sync exercise using two independent authenticated sessions, server-side Yjs state and application restart persistence.
- An application-quiesced PostgreSQL/config/storage backup with private recovery inputs, sanitized metadata and complete checksums.
- Independent fresh-project restore, pinned migration, semantic state equality and post-restore restart verification on Windows Docker Desktop linux/amd64.
- Ten focused regression tests, an expanded offline Phase 5 contract validator and documentation of the operator, safety and recovery boundaries.

## Release decision

Go for `0.6.0-alpha.4` as an experimental AFFiNE recovery module only after the standard cross-platform validation matrix passes on the exact tagged commit. No-go for stable `0.6.0`, production migration, production-backup replacement or an assertion that all AFFiNE clients/features are covered.

## Boundaries

The exercise validates a bounded Yjs text marker through the AFFiNE sync service, not a browser-rendered editor block tree. Desktop/mobile sync, attachments, comments, public access, SMTP, OAuth, AI, indexing, multi-user load and upgrade paths remain unverified. The backup contains private credentials and application data in plaintext; encryption, off-host storage, independent key custody, retention and clean-machine disaster recovery are not included.

The existing personal AFFiNE deployment remains outside this adapter. No personal users, notes, credentials, files or database rows were read, exported or changed.

## Next gate

Add an encrypted independently recoverable AFFiNE repository, prove decryption and application restore without source-host state, and add a browser-rendered document fidelity check before considering the AFFiNE substage complete. Nextcloud remains the next separate Phase 5 application after explicit approval.
