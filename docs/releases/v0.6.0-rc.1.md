# v0.6.0-rc.1 — Phase 5 integrated recovery candidate

This release candidate combines the six separately validated personal-data recovery modules behind one auditable disaster-recovery gate. It does not adopt existing deployments or configure production backup destinations.

## Included

- Paperless-ngx, AFFiNE, Nextcloud, Firefly III, Vaultwarden and Karakeep application-aware recovery contracts.
- Six checksum-pinned Restic vaults with portable manifests, full-data checks, separately referenced recovery keys and restore-gated 7/4/3 retention.
- Reusable manual recovery workflows with read-only repository permissions, explicit module-specific secrets, immutable action revisions and isolated artifact names.
- One manual integrated workflow that calls all six reviewed workflows on the same commit and contains no independent shell implementation.
- A machine-readable six-module assurance matrix and expanded offline validation for workflow, tool, API-shape, retention and evidence parity.
- A combined validation record with explicit production-adoption and stable-release blockers.

## Release decision

Go for `0.6.0-rc.1` only after the standard six-job validation matrix and all twelve prepare/recover jobs of the manual integrated recovery workflow pass on the exact commit. No-go for stable `0.6.0`, production migration or replacement of the owner's current backup process.

## Security and data boundaries

- All recovery fixtures are generated and synthetic.
- Recovery passwords are GitHub Actions secrets, never repository values or workflow artifacts.
- Encrypted repositories and sanitized manifests move between runners; key files and decrypted application sets do not.
- Each called workflow retains the original two-runner separation and performs a full Restic data check.
- Production services are not read for backup, stopped, restarted, reconfigured or adopted by this release.

## Remaining work

Durable owner storage, real offline-key custody, scheduled execution, alerts, production-data restore drills, measured recovery objectives, key rotation, large-data evidence and stable platform policy remain separate owner-approved gates. See the [integrated validation record](../validation/phase5-integrated.md).
