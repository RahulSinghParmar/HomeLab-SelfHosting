# v0.6.0-alpha.3 — Paperless off-host clean-runner recovery

Third bounded Phase 5 prerelease. **Phase 5 is not complete and production Paperless is not adopted.**

## Delivered

- Restic 0.19.1 Linux amd64 support locked to reviewed official archive and executable SHA-256 values, alongside the existing Windows amd64 support.
- A portable recovery manifest binding repository, snapshot, required tags, exact application manifest and semantic summary without source paths, keys, credentials or document titles.
- A confirmation-gated clean-host recovery plan that requires only the encrypted repository, portable manifest, independently supplied key and reviewed Restic binary.
- Mandatory full repository data verification before clean-host decryption.
- A manually dispatched two-runner workflow using an immutable encrypted artifact and a separately injected synthetic recovery secret.
- Independent Paperless importer recovery plus complete stop/start content verification on the clean runner.
- Immutable commit pins for checkout, Python setup and artifact transfer actions.

## Release decision

Go for `0.6.0-alpha.3` only when the standard six-job validation matrix and the separate two-job Paperless recovery rehearsal both pass on the exact tagged commit. No-go for stable `0.6.0`, production-backup replacement, production migration or unattended scheduling.

This release validates synthetic-data portability. GitHub Actions artifacts are short-lived validation transport, not the household backup destination. The repository secret is a synthetic test key, not the user's production recovery key.

## Remaining work

Select durable independently recoverable storage for production, create and document real offline-key custody, review the observed production export timing, run a guarded non-destructive production-scale backup, measure recovery point/time, decide scheduling and key rotation, and regenerate API tokens after restore. The other five Phase 5 applications have not started in this release.
