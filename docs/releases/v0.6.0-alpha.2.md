# v0.6.0-alpha.2 — Paperless encrypted recovery vault

Second bounded Phase 5 prerelease. **Phase 5 is not complete and no production application is adopted.**

## Delivered

- A separate `paperless-vault` command surface for reviewed restic tool validation, dual key-file generation, deterministic plans, repository initialization, encrypted store, full data check, restore, status and retention.
- Restic 0.19.1 Windows amd64 locked to an official release URL plus reviewed archive and executable SHA-256 values; no automatic or global installation.
- Owner-only operational/recovery key files in separate directories, secret-free output, environment cleanup, non-overlapping storage and repository-identity binding.
- Acceptance of only a complete, nonempty, checksum-verified `paperless` backup; snapshot confirmation binds the exact source manifest and semantic summary.
- Restore-before-protection behavior: a snapshot receives `recovery-verified` only after full decryption and Paperless backup verification.
- Restore-gated retention with a non-destructive preview, latest-snapshot full-check binding, 7 daily/4 weekly/3 monthly policy and preservation of the last verified point.
- Windows Docker Desktop evidence proving encrypted store, `check --read-data`, decrypted equality, independent Paperless importer recovery and stop/start persistence.
- Thirteen focused vault tests, an expanded Phase 5 contract validator and an explicit Phase 5 CI step.

## Release decision

Go for `0.6.0-alpha.2` as an experimental Windows amd64 encrypted recovery component. No-go for stable `0.6.0`, production-backup replacement, automated scheduling or disaster-recovery claims.

The validation repository and key copies were local and disposable, so `off_host_verified` remains false. The production Paperless project stayed healthy and unchanged. All synthetic containers, volumes, plaintext data, keys, encrypted repository and validation binary were removed after the trial.

## Remaining work

Prove an independently recoverable off-host repository and offline key on a clean machine, decide scheduling and key-rotation operations, and test representative production scale before considering the Paperless substage complete. API tokens, public/auth/mail/OCR/load/update behavior and Linux/macOS/ARM64 runtime remain unverified. The other five Phase 5 applications have not started in this release.
