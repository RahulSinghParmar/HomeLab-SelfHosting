# v0.6.0-alpha.8 — Firefly III application-aware recovery candidate

Eighth bounded Phase 5 prerelease. **Phase 5 is not complete and production Firefly III is not adopted.**

## Included

- Digest-pinned Firefly III 6.6.6, MariaDB 10.11.18 and Alpine 3.22 with loopback-only app access, internal database/cron networking, generated private secrets and bounded resources.
- Exact synthetic asset/expense transaction, 49-byte receipt, two supported exports, integrity report and real static-token cron validation.
- Quiesced, application-consistent backup containing an independently checked logical MariaDB dump, upload/export trees, private recovery inputs, sanitized metadata and complete checksums.
- Fresh-project recovery with live database verification, bounded one-shot ownership normalization, exact semantic content comparison and recovered stop/start persistence.
- Twelve focused tests, expanded offline Phase 5 validation and Windows Docker Desktop evidence.

## Release decision

Go for `0.6.0-alpha.8` only after the standard cross-platform matrix passes on the exact commit. No-go for stable `0.6.0`, production migration or replacement of the owner's backup process.

## Boundaries

The local staging backup contains credentials and is not encrypted. It was deleted after the rehearsal. This candidate does not provide off-host storage, retention, scheduling, independent recovery-key custody, importer/bank integrations, public access validation, multi-user/load testing, upgrade rollback or non-Windows runtime evidence.

The existing personal Firefly deployment remained outside this adapter. No personal users, accounts, balances, transactions, attachments, credentials or database rows were read, exported or changed.

## Next gate

Encrypted off-host Firefly recovery is a separate milestone requiring a reviewed backup tool, independent key custody, encrypted-only transfer and fresh-runner application restore. No Vaultwarden work begins without a separate command.
