# v0.7.0-alpha.2 — Immich protected-original recovery

This prerelease adds a bounded, isolated Immich 3.3.5 application-aware recovery candidate on top of the Phase 6 media safety foundation.

## Included

- Loopback-only server access with internal-only PostgreSQL, Valkey and ML networking.
- Exact digest-pinned images and ownership/drift checks.
- A private database secret file rather than a password embedded in Compose.
- Synthetic admin creation, PNG upload and byte-exact original download.
- Independently stoppable CPU machine learning limited to 1 CPU, 1536 MiB, 256 PIDs and one worker/thread lane.
- A quiesced custom PostgreSQL archive plus protected `library`, `upload` and `profile` content.
- Derived-media and model-cache exclusion with only required `.immich` integrity markers retained.
- Independent fresh-project application restore and post-restart original verification.
- Windows Docker Desktop evidence and an offline release validator.

## Validation result

The synthetic original recovered with SHA-256 `0054b8401f90de27aa1243f1d8e078b113f21137921961b6aa67a35602f60573`. Source and restored projects both passed health checks; original browsing remained available while ML was stopped. All disposable runtime state and plaintext-sensitive backup data were removed after validation.

## Boundaries

This is not production adoption. It does not inspect or migrate the existing household Immich deployment, provide encrypted off-host retention, enable GPU acceleration, mount external libraries, regenerate a full derivative set, validate mobile clients or schedule backups. The reference GT 730 remains unsupported for current Immich CUDA requirements.

See the [module guide](../immich-module.md) and [validation evidence](../validation/immich.md).
