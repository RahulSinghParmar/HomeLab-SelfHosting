# v0.7.0 — Phase 6 media recovery and acceleration kit

Version 0.7.0 completes the bounded Phase 6 public toolkit for protected media recovery, optional media-management integrations and backend-specific acceleration decisions.

## Included

- Immich protected-original recovery, separately limited CPU machine learning and encrypted clean-runner recovery.
- Explicit native/container Jellyfin ownership, same-version application recovery, separately encrypted owner-managed media recovery and exact direct play after restart.
- Eight individually selectable media-management applications with immutable image references, dependency checks, loopback/internal access and no implicit activity.
- Stopped-state media-management configuration backup, SQLite integrity checks, shared-filesystem semantics, independent restore and measured resource evidence.
- Native Windows Intel QSV CPU/single-stream/two-stream/HEVC synthetic measurements with decoded-output and quality validation.
- CPU fallback and explicit rejection of the reference GT 730 NVENC path.

## Release gate

Publish only after the exact commit passes the six-job cross-platform validation matrix, including the new Phase 6 closure validator and complete regression suite. Do not move or reuse the tag.

## Scope boundary

Stable `0.7.0` means the versioned synthetic recovery and acceleration contracts are complete. It does not migrate the existing `arr-stack`, configure indexers/providers/downloads, rotate private integration tokens, read production media, adopt physical off-host storage, schedule production backups or certify production client/concurrency behavior. HDR tone mapping, Intel low-power encoding and four-stream transcoding remain separate gates.
