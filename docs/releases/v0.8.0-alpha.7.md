# 0.8.0-alpha.7 — Coolify controller integration

> Superseded by 0.8.0-alpha.8 after Linux and macOS CI identified platform-specific interpretation of the Windows custom-Compose path. The live controller was not affected.

Released 2026-11-18.

## Included

- A strict Coolify controller policy, sanitized audit, tamper-evident plan and CLI commands.
- Live Windows Docker Desktop checks covering Docker/Compose identity, WSL mount access, owner tasks, backup freshness, updater-shim anchors and Sentinel resource ceilings.
- Official stable-channel discovery without pulling images or starting an update.
- Optional secret-file API authentication for aggregate active-deployment checks; tokens are never persisted.
- Explicit handoff from the generic Docker update manager to the Coolify controller for root, proxy and generated application projects.
- A central PowerShell `Controller` action on the reference host.
- Soketi-to-Reverb migration detection and documented recovery/update gates.

## Reference-host result

The healthy 4.5.3 instance can see stable 4.7.5, but the plan correctly remains blocked. Windows is not an upstream-supported host, encrypted off-host instance recovery is unproven, no read-only API token is configured, and the target crosses the Reverb migration boundary. Sentinel limits and all reviewed Windows compatibility checks pass.

No image was pulled, no update or migration was started, no service was restarted, and no secret was added to the repository.
