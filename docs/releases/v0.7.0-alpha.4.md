# 0.7.0-alpha.4 — Jellyfin explicit deployment selection

Date: 2026-11-09

## Included

- A privacy-bounded audit that distinguishes native, container, absent and conflicting Jellyfin ownership.
- A mandatory `native` or `container` selection with no automatic deployment choice.
- Fail-closed platform rules: native-only on Windows/macOS and either explicit choice on Linux.
- Refusal to change an existing deployment type without a separately reviewed migration.
- An immutable official Jellyfin 12.4 container reference and a Linux-only Compose renderer.
- Loopback-only container access, read-only media, non-root identity, resource limits and restricted privileges.
- An application-backup contract based on Jellyfin's built-in archive and same-version restoration.
- CPU fallback with a synthetic codec/transcode gate before any device access.

## Validation

- The reference Windows host was detected as a running, automatic native Jellyfin 12.4.0 service with no Jellyfin container.
- The live audit read no credentials or media and performed no mutation.
- The official 12.4 multi-platform image digest was queried without pulling or starting a container.
- Focused tests covered explicit selection, platform rejection, conflicting ownership, plan drift, read-only media and restricted Compose rendering.
- The reference GT 730/391.35 combination remained CPU-only; no production playback or synthetic transcode was started.

Release requires repository, Phase 4/5/6, publication, complete regression and whitespace validation on the exact commit.

## Not included

- Native installation/update automation or container deployment.
- Production migration or deployment-type conversion.
- Library, playlist, user, plugin or media changes.
- Playback/client/concurrency tests or hardware transcoding.
- Application restore, encrypted off-host recovery or stable Phase 6 completion.
