# 0.2.0 — Discovery and configuration mapping

Phase 1 adds evidence-backed reference runbooks and read-only discovery tooling. It is a prerelease blueprint, not an application installer.

## Included

- 21 module runbooks with source locators, lifecycle ownership, storage, secret names/purposes, custom settings, operations and recovery requirements.
- A machine-readable coverage ledger reconciling 54 observed containers, including two excluded personal controller-generated workloads.
- Evidence from 19 Compose source combinations, with 17 resolvable locally and two transient source paths explicitly unresolved.
- Windows metadata collector with privacy filtering, no-overwrite/outside-repository checks, and mocked regression tests.
- Backup/reproducibility findings and custom-build provenance, including untracked patch requirements.

## Important findings

Coolify's alternate source set selects a different app version from the live/root configuration. Several existing backup scripts need portability, consistency or coverage improvements before reuse. Native startup, custom images and external account state require explicit adapters or owner steps.

Read [the findings](../discovery/findings.md) and [scope/evidence limits](../discovery/evidence.md). Reported historical restore status is not a new recovery test.

## Validation and safety

Repository and Python tests cover all three CI operating systems. Windows additionally runs mocked collector privacy/grouping/output-guard tests. Live discovery did not start, stop, restart, update or adopt services, and did not read user document/media/vault/finance content.

Raw inventory, actual paths/identities, credentials and data remain outside Git. No third-party application source or live Compose configuration is bundled.

Next: Phase 2, the cross-platform doctor, wizard and deterministic planning engine. Deployment remains disabled until later phases.
