# v0.6.0-alpha.9 — Firefly III encrypted off-host recovery candidate

## Scope

This prerelease extends the isolated Firefly III recovery module with a reviewed Restic 0.19.1 vault and a clean-runner disaster-recovery gate. It uses generated non-personal finance data only and never contacts, adopts or modifies the owner's production Firefly deployment.

## Delivered

- Exact Windows amd64 and Linux amd64 Restic archive/executable checksums, with no global installation or inherited `RESTIC_*` configuration.
- Distinct operational and recovery key files, private state, non-overlapping storage and confirmation-gated mutation.
- Encrypted store, full repository data check, manifest-bound decrypt, protected restore evidence and restore-gated 7 daily/4 weekly/3 monthly retention.
- A portable manifest binding the repository, snapshot, complete Firefly backup manifest, transaction count, raw attachment size/hash, and upload/export file counts.
- A manually dispatched two-runner workflow that transfers only the encrypted repository and nonsecret manifest while injecting the synthetic recovery secret separately.
- Fresh-runner application recovery that restores MariaDB plus upload/export state, verifies the exact finance fixture, and repeats verification after stop/start.
- POSIX file-backed secret handling that preserves owner-only parent directories while granting the non-root Firefly process only the read bit required by Docker Compose's bind-mounted secret model; Windows retains owner-scoped ACLs.
- Eighteen focused encrypted-vault tests, one new POSIX secret-permission regression test, and expanded release, security and platform validation contracts.

## Release gate

Go for `0.6.0-alpha.9` only after the standard cross-platform matrix and both jobs of the Firefly III off-host recovery rehearsal pass on the exact commit. No-go for stable `0.6.0`, production migration or replacement of the owner's backup process.

## Boundaries

The hosted rehearsal uses short-lived synthetic data and an expiring encrypted artifact. It does not provide durable owner-operated off-host storage, prove real offline-key custody, schedule production backups, rotate keys, migrate personal finance records, test bank/import integrations, validate public access, establish recovery objectives or represent production scale.

The owner's existing Firefly containers and data remain outside this module. Production adoption requires separately chosen storage destinations, independent key custody, scheduling, retention ownership and an explicitly authorized real-data rehearsal.
