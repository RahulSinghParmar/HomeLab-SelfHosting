# v0.6.0-alpha.10 — Vaultwarden application-aware recovery candidate

Tenth bounded Phase 5 prerelease. **Phase 5 is not complete and production Vaultwarden is not adopted.**

## Included

- Digest-pinned Vaultwarden 1.37.1 and Playwright/Chromium 1.64.0 with loopback-only app access, a private bridge, generated credentials and bounded resources.
- Rendered Web Vault registration, encrypted secure-note creation/decryption, 49-byte attachment upload/download, full reload/unlock, independent-session and source-restart verification.
- Built-in consistent SQLite backup plus quiesced RSA key, attachment, Send and optional configuration capture with sanitized metadata and complete checksums.
- Fresh-project recovery with exact browser-decrypted content and attachment bytes, followed by recovered restart persistence.
- Nine focused tests, expanded offline Phase 5 validation and Windows Docker Desktop evidence.
- A 30-minute CI job ceiling so the complete Windows ACL/locking regression suite can finish on both supported Python versions without weakening the six-job matrix.

## Release decision

Go for `0.6.0-alpha.10` only after the standard cross-platform matrix passes on the exact commit. No-go for stable `0.6.0`, production migration or replacement of the owner's backup process.

## Boundaries

The local staging backup contains generated credentials and is not encrypted. Registration is enabled and the admin route disabled only for the disposable loopback fixture. The internal browser helper uses ephemeral self-signed TLS solely to provide Web Crypto's secure context; the module creates no public endpoint.

This candidate does not validate organizations, Sends semantics, TOTP/passkeys, emergency access, native clients/extensions, SMTP, public access, multi-user/load behavior, upgrade rollback, encrypted off-host storage, scheduling, retention or non-Windows runtime behavior.

The existing personal Vaultwarden deployment remained outside this adapter. No personal users, items, attachments, credentials, configuration values or database rows were read, exported or changed.

## Next gate

Encrypted off-host Vaultwarden recovery is a separate milestone requiring a reviewed backup tool, independent recovery-key custody, encrypted-only transfer and fresh-runner browser decryption plus attachment restore. No Karakeep work begins without a separate command.
